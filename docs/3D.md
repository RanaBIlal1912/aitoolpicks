# 3D and WebGL on this site

The site does load WebGL, in exactly two places. Everything else (including the first paint of both pages) is plain HTML and SVG. This file is the reference for what loads, when, and what a visitor gets when 3D is unavailable. A test (`tests/three-d.test.ts`) fails if a file that uses Three.js or WebGL is not listed here.

## 1. Home page hero: the 3D robot (worker-driven)

| Part | File | What it is |
| --- | --- | --- |
| Hero artwork | `src/components/home/RobotHero.tsx` | A flat SVG robot is in the HTML at once. A 3D robot is drawn on a canvas over it and fades in when ready. |
| 3D renderer | `src/components/hero/robot.worker.ts` | Runs Three.js on an `OffscreenCanvas` inside a Web Worker, so building and drawing the scene never runs on the page's main thread. |
| Backdrop | `src/components/hero/HeroVisual.tsx` | **No WebGL.** Plain SVG network plus floating logos. |
| Helpers | `src/lib/motion3d.ts`, `src/lib/constellation.ts` | Opt-in storage; the network layout used by the SVG backdrop. |

**When it starts.** About 2.7 s after the page has loaded (once the browser is idle), or on the first interaction (move, touch, key, scroll), whichever is first. The canvas is handed to the worker once.

**What keeps the flat robot (nothing is hidden, the page looks complete):**
- no `Worker`, `OffscreenCanvas` or `transferControlToOffscreen` support;
- no WebGL, or a software-only renderer;
- `prefers-reduced-motion: reduce` or Save-Data. The hero then shows a "Turn on 3D animation" button. Pressing it switches 3D on and is remembered in this browser (`localStorage` key `aitp-3d`);
- JavaScript off.

**Phones and tablets.** Below 1024 px wide the worker gets the compact scene (robot centred, cube close). Touch steers the robot. Drawing pauses when the hero is off screen or the tab is hidden. `?robot=3d` in the address forces the scene on a software renderer for testing.

## 2. Ecosystem page: the 3D network (main thread, lazy)

| Part | File | What it is |
| --- | --- | --- |
| Section | `src/components/universe/EcosystemNetwork.tsx` | Builds the graph from verified records, decides when to load the scene, and shows the fallback text. |
| Scene | `src/components/universe/EcosystemScene.tsx` | React Three Fiber scene with orbit controls. Loaded with `next/dynamic` (`ssr: false`), so Three.js is not in the page's first JavaScript. |
| Labels | `src/components/universe/Label.tsx` | Node labels drawn inside the scene. |

**When it loads.** Not at page start. An `IntersectionObserver` waits until the section is within 300 px of the viewport, then `whenEngaged` (`src/lib/engage.ts`) waits for the first interaction or 10 s. The WebGL check runs only at that point.

**Fallbacks.**
- Before it loads, or without WebGL: a short message, and the company, product and model lists further down the page carry the same information.
- `prefers-reduced-motion` or Save-Data: the scene stays off and the section offers a **Show the 3D network** button (the same remembered choice as the hero).
- Phones (under 768 px): a shorter frame (380 px instead of 560 px). The page does not capture the scroll wheel; zoom is by buttons.

## 3. Build-time only: cover renders

`src/lib/scene/` and `scripts/covers/` are used by `npm run covers` to render images offline. No page imports them and nothing in them ships to visitors.

## Removed

The earlier 3D "universe" map (`UniverseSection`, `UniverseScene`), the main-thread hero scene (`HeroScene`) and its lighting rig (`Studio`) were not used by any page and were deleted. The home hero no longer has a main-thread WebGL path.

## Checking it yourself

1. Home page, desktop: after about 3 s a `<canvas>` appears in the hero and a `turbopack-worker…` script loads.
2. Ecosystem page: no `<canvas>` at load; scroll to "The network" and one appears.
3. DevTools, Rendering, emulate "prefers-reduced-motion: reduce": both scenes stay off and show their opt-in buttons.
4. Performance numbers live in `docs/LIGHTHOUSE.md`.
