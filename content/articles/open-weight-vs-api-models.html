Developers building with AI face a choice before they write any code: use a closed model through its maker's API, rent an open model from an inference provider, or run an open model on their own machine. Each route trades money, control, privacy and effort differently.

How this guide was made: it is a documentation-based overview. We read each vendor's official pages and recorded plans, prices and limits on the date shown; we have not run hands-on tests or benchmarks, so nothing here is a performance claim. Prices change, so confirm on the official page before you pay.

The three routes

  • Closed API: you pay the vendor per use and get its latest models without running anything yourself.
  • Hosted open models: an inference platform runs open models for you and bills by use. Prices and available models vary by provider.
  • Local open models: you run a model on your own hardware. The software can be free, but the hardware, setup and updates are yours.

What "open" can mean

Not every "open" model has the same licence. Some are fully open source, some publish weights under a custom licence with limits on commercial use, and some tools are source-available rather than open source. Read the licence before you build a product on a model; our tool pages show an open-source status only where the official repository states it.

How to choose

  • Prototyping: a hosted API is quickest; compare per-token or per-run prices on a small test workload.
  • Private data or no internet: a local model keeps data on your machine, at the cost of hardware and maintenance.
  • Cost at scale: estimate monthly tokens or run time first, because pay-per-use grows with traffic and fixed GPU rental does not.
  • Avoiding lock-in: a router or an open model you can move between hosts keeps your options open.
